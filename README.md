# CCTV Monitor

![CI](https://github.com/mikhail3391/cctv-monitor/actions/workflows/ci.yml/badge.svg)

Небольшой сервис на FastAPI для администратора видеонаблюдения. Ведёт реестр камер,
следит за их статусом (online/offline), записывает события (движение, вмешательство) и
считает, сколько места нужно под архив записей. Например: 8 камер по 4 Мбит/с, хранить
14 дней, запас 20 %, итого около 5,81 ТБ. Сервис не принимает видео: в нём только данные
о камерах и событиях, без паролей и адресов потоков.

## Маршруты

- `/cameras`: список камер, можно фильтровать (`?status=offline&location=холл`);
  `POST` добавляет камеру
- `/cameras/{id}`: одна камера
- `/cameras/{id}/status`: `PATCH` меняет статус на `online` или `offline`
- `/cameras/{id}/events`: `POST` записывает событие `motion` или `tamper`
- `/events?camera_id=1&type=tamper&limit=20`: журнал событий, новые сверху
- `/summary`: сколько камер работает, какие offline, сколько событий каждого типа
- `/storage/estimate?cameras=8&bitrate_mbps=4&days=14`: сколько места нужно под архив;
  `&reserve_percent=30` меняет запас (по умолчанию 20)
- `/storage/required`: сколько места нужно под все добавленные камеры
- `/`, `/health`, `/version`: приветствие и служебные проверки

События `offline` и `online` сервис записывает сам, когда меняется статус камеры. Время
события без часового пояса считается UTC. Если камеры с таким id нет, сервис вернёт 404,
если данные неверные (пустое имя, битрейт 0, неизвестный статус) — 422 с описанием
ошибки. Данные хранятся в памяти: после перезапуска список камер и событий пуст.

Место считается так: 1 Мбит/с за сутки это 10,8 ГБ (десятичные ГБ и ТБ).

## Установка

Нужен Python 3.12 или новее.

```bash
git clone https://github.com/mikhail3391/cctv-monitor.git
cd cctv-monitor
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

На Windows: `python -m venv .venv`, затем `.venv\Scripts\activate`.

В `requirements.txt` то, что нужно для работы сервиса, в `requirements-dev.txt` то же
плюс pytest и httpx для тестов.

## Запуск

```bash
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Документация, где можно отправлять запросы прямо из браузера: http://127.0.0.1:8000/docs

Во время разработки удобно добавить `--reload`: сервер сам перезапустится после
сохранения кода.

## Проверка

```bash
curl http://127.0.0.1:8000/health     # {"status":"ok","uptime_seconds":12}
curl http://127.0.0.1:8000/version    # {"app":"CCTV Monitor","version":"1.0.0","author":"Не указан"}
```

Попробовать сервис в деле:

```bash
curl -X POST http://127.0.0.1:8000/cameras -H "Content-Type: application/json" \
  -d '{"name": "Вход", "location": "Холл, 1 этаж", "bitrate_mbps": 4}'
curl -X PATCH http://127.0.0.1:8000/cameras/1/status -H "Content-Type: application/json" \
  -d '{"status": "offline"}'
curl http://127.0.0.1:8000/summary
curl "http://127.0.0.1:8000/storage/estimate?cameras=8&bitrate_mbps=4&days=14"
```

## Настройки

Задаются переменными окружения, шаблон лежит в `.env.example`. После изменения
перезапустите сервер. Сам `.env` в Git не попадает.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `APP_NAME` | `CCTV Monitor` | название в `/` и `/version` |
| `APP_AUTHOR` | `Не указан` | автор в `/version` |
| `RETENTION_DAYS` | `14` | сколько дней хранить записи (от 1 до 3650), по умолчанию для расчёта места |
| `LOG_LEVEL` | `INFO` | подробность логов: `DEBUG`, `INFO`, `WARNING`, `ERROR` |

Сервис сам файл `.env` не читает. Чтобы применить настройки из него, перед запуском
выполните `cp .env.example .env`, отредактируйте файл и загрузите его в терминал:

```bash
set -a; source .env; set +a
```

Одну переменную можно задать и прямо в команде запуска: `RETENTION_DAYS=30 python -m uvicorn ...`.
На Windows (PowerShell) перед запуском: `$env:RETENTION_DAYS = "30"`.

## Логи

Пишутся в терминал, где запущен сервер: запуск приложения, каждый запрос, смена статуса
камеры, события и ошибки.

```
2026-10-25 12:00:23,558 INFO cctv_monitor: Сервис запущен: app='CCTV Monitor' version=1.0.0 retention_days=14
2026-10-25 12:00:25,778 INFO cctv_monitor: Добавлена камера id=2 'Парковка' (Двор), 8.0 Мбит/с
2026-10-25 12:00:25,788 WARNING cctv_monitor: Камера id=2 'Парковка' (Двор) перешла в offline
2026-10-25 12:00:25,797 WARNING cctv_monitor: Возможное вмешательство: камера id=1 'Вход' (Холл, 1 этаж)
2026-10-25 12:00:25,819 INFO cctv_monitor: GET /summary -> 200 (0.8 мс)
```

Чтобы сохранить логи в файл, добавьте к команде запуска `2>&1 | tee app.log`.

## Тесты

```bash
python -m pytest -v
```

Тесты проверяют камеры и фильтры, смену статуса, события, сводку, расчёт места, `/health`,
`/version`, ошибки ввода и сообщения в логах. Сервер для них запускать не нужно. Те же
тесты запускает GitHub Actions при каждом push и pull request. Если они прошли,
сохраняется artifact с файлами приложения: вкладка Actions, последний запуск, раздел
Artifacts.

## Диагностика

- `command not found: python` или `No module named ...`: не активировано окружение,
  выполните `source .venv/bin/activate`.
- `Address already in use`: порт занят старым сервером. Найдите его через `lsof -i :8000`
  и остановите командой `kill <PID>` или запустите на другом порту (`--port 8001`).
- `curl: (7) Couldn't connect to server`: сервер не запущен или указан другой порт.
- `zsh: no matches found`: адрес с `?` нужно взять в кавычки.
- Поменяли `.env`, а ничего не изменилось: файл сам не читается, загрузите его командой
  `set -a; source .env; set +a` и перезапустите сервер.
- В логе при запуске `Неверный RETENTION_DAYS` или `Неизвестный LOG_LEVEL`: значение не
  подошло (нужно целое число от 1 до 3650 или один из уровней логов), сервис взял значение
  по умолчанию.
- Код 422: параметр не передан или имеет неверный вид, причина написана в поле `detail`.
  Код 404: камеры с таким id нет.
- Список камер пуст после перезапуска: данные хранятся только в памяти.
- Время в `/events` отличается от вашего: события хранятся в UTC (Москва это UTC+3).
