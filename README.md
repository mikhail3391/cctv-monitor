# CCTV Monitor (FastAPI)

Небольшой сервис для администратора системы видеонаблюдения: в нём можно вести реестр
камер, отмечать их статус (online/offline), записывать события (движение, вмешательство)
и считать, сколько места нужно под архив записей.
Предназначен для сисадмина или ответственного за видеонаблюдение в небольшом офисе,
магазине или складе, которому нужен простой учёт без сложных систем.

Сервис ничего не снимает и не принимает видеопоток: он хранит только данные о камерах
и событиях (без паролей, адресов потоков и записей).

Проект — итоговая работа по курсу «Инфраструктура и администрирование»:
код → Git → тесты → автоматическая проверка (GitHub Actions) → понятный запуск и диагностика.

Основа: учебный `app_final.py` (занятие 04 «FastAPI: реализуем приложение вместе»).
Что добавлено сверх учебного примера:

- своя тема и маршруты: камеры, события, сводка, расчёт хранилища;
- параметры: путь (`/cameras/{id}`), фильтры (`status`, `location`, `type`, `camera_id`),
  параметры расчёта (`cameras`, `bitrate_mbps`, `days`, `reserve_percent`);
- настройки из переменных окружения (название, автор, срок хранения, уровень логов);
- `/version` и логи запуска, каждого запроса и важных событий (камера пропала, вмешательство);
- автоматические тесты (`test_app.py`) и CI в GitHub Actions.

## Что лежит в репозитории

```text
app_final.py                 приложение
test_app.py                  тесты
requirements.txt             зависимости для запуска
requirements-dev.txt         зависимости для тестов (включает requirements.txt)
.env.example                 шаблон настроек (без секретов)
.gitignore                   что не попадает в Git (.env, .venv, кэши)
.github/workflows/ci.yml     автоматическая проверка в GitHub Actions
```

## Установка

Нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python -m pip install -r requirements-dev.txt
```

Для запуска без тестов достаточно `requirements.txt`.

## Настройки (переменные окружения)

Все настройки необязательные — у каждой есть значение по умолчанию.

| Переменная       | По умолчанию  | Что делает                                                               |
| ---------------- | ------------- | ------------------------------------------------------------------------ |
| `APP_NAME`       | `CCTV Monitor`| Название сервиса в `/` и `/version`                                      |
| `APP_AUTHOR`     | `Не указан`   | Автор в `/version`                                                       |
| `RETENTION_DAYS` | `14`          | Сколько дней хранить записи (1–3650); влияет на расчёт места под архив   |
| `LOG_LEVEL`      | `INFO`        | Уровень логов: `DEBUG`, `INFO`, `WARNING`, `ERROR`                       |

Пример: создать свой файл настроек и применить его.

```bash
cp .env.example .env               # затем отредактируйте .env
set -a; source .env; set +a        # загрузить переменные в текущую консоль
```

Файл `.env` в Git не попадает (он в `.gitignore`), публиковать нужно только `.env.example`.
Настройки применяются при запуске: изменили переменную — перезапустите приложение.

## Запуск

Обычная работа (без `--reload`):

```bash
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Для разработки (перезапуск при изменении кода):

```bash
python -m uvicorn app_final:app --reload
```

После запуска:

- приложение: <http://127.0.0.1:8000>
- интерактивная документация: <http://127.0.0.1:8000/docs>

## Маршруты

| Метод и путь                      | Что делает                                                                       |
| --------------------------------- | -------------------------------------------------------------------------------- |
| `GET /`                           | Приветствие и ссылка на `/docs`                                                  |
| `GET /health`                     | Проверка работоспособности: `{"status": "ok", "uptime_seconds": ...}`            |
| `GET /version`                    | Версия приложения, название и автор                                              |
| `POST /cameras`                   | Добавить камеру (`name`, `location`, необязательный `bitrate_mbps`, по умолч. 4) |
| `GET /cameras`                    | Список камер; параметры `status` (`online`/`offline`) и `location` (часть текста)|
| `GET /cameras/{id}`               | Одна камера (404, если нет)                                                      |
| `PATCH /cameras/{id}/status`      | Сменить статус: `{"status": "offline"}`; смена записывается как событие          |
| `POST /cameras/{id}/events`       | Записать событие: `{"type": "motion"}` или `{"type": "tamper"}`                  |
| `GET /events`                     | События от новых к старым; параметры `camera_id`, `type`, `limit`                |
| `GET /summary`                    | Сколько камер online/offline, какие offline, сколько событий каждого типа        |
| `GET /storage/estimate`           | Калькулятор: параметры `cameras`, `bitrate_mbps`, `days`, `reserve_percent`      |
| `GET /storage/required`           | Сколько места нужно под все добавленные камеры; параметр `reserve_percent`       |

Как считается место: 1 Мбит/с за сутки — это 10,8 ГБ (десятичные ГБ и ТБ).
Например, 8 камер по 4 Мбит/с на 14 дней с запасом 20 % — около 5,81 ТБ.

Типы событий: `motion` (движение) и `tamper` (вмешательство) присылает пользователь;
`offline` и `online` сервис записывает сам при смене статуса. Время события без часового
пояса считается UTC. Событие `tamper` и переход камеры в `offline` попадают в лог как предупреждения.

Данные хранятся в памяти: после перезапуска сервиса список камер и событий пуст.
Для учебного проекта база данных не нужна.

## Быстрая проверка

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/version

curl -X POST http://127.0.0.1:8000/cameras \
  -H "Content-Type: application/json" \
  -d '{"name": "Вход", "location": "Холл, 1 этаж", "bitrate_mbps": 4}'

curl -X PATCH http://127.0.0.1:8000/cameras/1/status \
  -H "Content-Type: application/json" \
  -d '{"status": "offline"}'

curl -X POST http://127.0.0.1:8000/cameras/1/events \
  -H "Content-Type: application/json" \
  -d '{"type": "motion", "note": "Движение у двери"}'

curl "http://127.0.0.1:8000/cameras?status=offline"
curl "http://127.0.0.1:8000/events?camera_id=1"
curl http://127.0.0.1:8000/summary
curl "http://127.0.0.1:8000/storage/estimate?cameras=8&bitrate_mbps=4&days=14"
curl http://127.0.0.1:8000/storage/required
```

## Тесты

```bash
python -m pytest -v
```

Тесты проверяют `/health`, `/version`, добавление камер и фильтры, смену статуса и события,
сводку, расчёт хранилища, ошибки (404 и 422), настройки из окружения и сообщения в логах.

## Автоматическая проверка (CI)

Файл `.github/workflows/ci.yml` запускается при каждом `push` и `pull request`:
устанавливает зависимости, запускает `python -m pytest -v` и, если тесты прошли,
сохраняет файлы приложения как artifact `app-files`.
Результаты — на вкладке **Actions** репозитория; artifact находится внизу страницы запуска.

## Логи и диагностика

Логи выводятся в консоль, где запущен сервис (stdout/stderr). Чтобы сохранить их в файл
и одновременно видеть на экране:

```bash
python -m uvicorn app_final:app 2>&1 | tee app.log
```

Пример записей:

```text
2026-10-25 12:00:23,558 INFO cctv_monitor: Сервис запущен: app='CCTV Monitor' version=1.0.0 retention_days=14
2026-10-25 12:00:25,778 INFO cctv_monitor: Добавлена камера id=2 'Парковка' (Двор), 8.0 Мбит/с
2026-10-25 12:00:25,788 WARNING cctv_monitor: Камера id=2 'Парковка' (Двор) перешла в offline
2026-10-25 12:00:25,797 WARNING cctv_monitor: Возможное вмешательство: камера id=1 'Вход' (Холл, 1 этаж)
2026-10-25 12:00:25,819 INFO cctv_monitor: GET /summary -> 200 (0.8 мс)
2026-10-25 12:00:25,827 INFO cctv_monitor: Расчёт хранилища: камер=8, битрейт=4.0 Мбит/с, дней=14 -> 5.81 ТБ
```

Если что-то не работает:

| Симптом                                      | Что проверить                                                                              |
| -------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `curl /health` не отвечает                   | Запущен ли сервис; нет ли ошибки в последних строках лога; тот ли порт                     |
| `Address already in use`                     | Порт занят — запустите с другим: `--port 8001`                                             |
| `ModuleNotFoundError: No module named ...`   | Не активировано окружение или не установлены зависимости: `source .venv/bin/activate`, затем `python -m pip install -r requirements.txt` |
| Ответ 422                                    | Неверные данные запроса — в поле `detail` указано, какое поле и почему                     |
| Ответ 404 на `/cameras/N`                    | Камеры с таким id нет (после перезапуска сервиса данные очищаются)                         |
| Срок хранения не такой, как в `RETENTION_DAYS` | В логе запуска ищите `Неверный RETENTION_DAYS`; задайте целое число от 1 до 3650 и перезапустите |
| Настройки не применились                     | Переменные нужно задать в той же консоли до запуска; затем перезапустить сервис            |
| Нужно больше деталей в логах                 | Запустить с `LOG_LEVEL=DEBUG`                                                              |
| Тесты падают                                 | Установлены ли зависимости из `requirements-dev.txt`; запускайте из папки проекта          |
